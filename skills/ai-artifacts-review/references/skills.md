# Skill Files Audit Checks

Skill format should be compatible across VS Code, Cursor, and Claude. References:

- [VS Code Agent Skills](https://code.visualstudio.com/docs/copilot/customization/agent-skills)
- [Cursor Agent Skills](https://cursor.com/docs/skills)

For each `SKILL.md`, check:

| Code | Check                                           | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|------|-------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| FM01 | `name` present and correct                      | Required. Must be lowercase with hyphens. Must exactly match the parent directory name                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| FM02 | `description` discoverable                      | Required. Must answer both *what* and *when*. Must start with "You SHOULD use this skill ..." followed by a concise description of conditions/scenarios when the skill should be invoked                                                                                                                                                                                                                                                                                                                                                                                   |
| FM03 | `user-invocable` declared                       | Set to `true` if user can invoke manually; `false` or absent if auto-only                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| FM04 | `argument-hint` present                         | Required when the skill accepts arguments                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| FM05 | `description` brevity                           | `description` must be at most 2 sentences (1 preferred). Keep it short and actionable - it is shown in skill lists and used for matching, not for documentation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| PA01 | Output paths match repo convention              | Any paths the skill creates or references must be consistent with the repo's own artifact layout (e.g., if the repo uses `.copilot/skills/`, new artifacts should not go to `.github/skills/`, and vice versa)                                                                                                                                                                                                                                                                                                                                                             |
| PA02 | Referenced assets exist                         | Every file referenced in the skill body (e.g., templates, assets) must actually exist in the skill directory                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ST01 | Procedure is complete                           | Must have: goal, when-to-use, inputs, step-by-step procedure, output format                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ST02 | Branching logic covers edge cases               | Conflicting sources, ambiguous patterns, low-confidence cases must have explicit handling rules                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ST03 | Quality gates defined                           | Completion criteria must be checkable - "done when all X are true"                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ST04 | Output contract explicit                        | The exact structure of output must be defined so results are predictable across invocations                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ST05 | File length ≤ 250 lines                         | `SKILL.md` must not exceed 250 lines. Skills exceeding this limit should extract reusable content into asset files under the skill directory                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ST06 | Context-efficient references by file type       | If a single `SKILL.md` contains rules for multiple file types, move the file-type-specific instructions into separate reference files directly inside `references/` (for example `references/instructions.md`, `references/prompts.md`, `references/skills.md`, `references/agents.md`). In `SKILL.md`, keep only links to those files and a mandatory, explicit condition for each link (for example: "read this file only when reviewing prompts"). Do not require reading unrelated reference files when those file types were not passed as input or are out of scope. |
| ST07 | Templates extracted to assets                   | Inline templates are allowed if ≤ 10 lines. Templates longer than 10 lines should be moved to `assets/` with only a brief reference in `SKILL.md`                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ST08 | Scripts used only when execution is predictable | Flow parts may be moved to `scripts/` only when execution is safely automatable in a known environment; this is rare because skills often cannot assume runtime/tool availability                                                                                                                                                                                                                                                                                                                                                                                          |
